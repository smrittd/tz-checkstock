# CheckStock

Прототип учёта товаров на складах фулфилмента: приходы, перемещения, заказы FBS,
поставки FBO, остатки и история операций.

**Стек:** Python 3.12, FastAPI, PostgreSQL 17, асинхронный SQLAlchemy + asyncpg,
Alembic. Frontend — HTML, CSS и JavaScript; Nginx. Запуск через Docker Compose.

## Запуск

Нужны запущенный Docker и Docker Compose v2. Из корня репозитория выполните:


docker compose up --build -d --wait


- [Веб-интерфейс](http://localhost:8080)
- [Swagger — документация и проверка API](http://localhost:8000/docs)
- [Проверка готовности API и БД](http://localhost:8000/health/ready)

Миграции и демо-данные загружаются автоматически. Повторный запуск не дублирует
товар; данные сохраняются в Docker volume. Устанавливать Python или Node.js
для запуска приложения не нужно. Файл `.env` необязателен.

Если порты заняты, скопируйте `.env.example` в `.env` и измените `WEB_PORT` (8080),
`API_PORT` (8000) или `POSTGRES_PORT` (5433).

## Проверка в интерфейсе


Создавайте действия кнопкой **«Новая операция»**, завершайте их в **«Операциях»**.
Сценарий для проверки на начальных данных:

1. **Нехватка:** создайте FBS на 12 единиц SKU-101 с Севера. Появится ошибка:
   на Севере доступно 10, хотя всего на складах 16. Остатки не изменятся.
2. **Перемещение:** отправьте 2 единицы SKU-101 с Юга на Север. До приёмки
   они отображаются в пути. Нажмите «Принять»: Север — 12, Юг — 4.
3. **FBS:** зарезервируйте 3 единицы SKU-101 на Севере, указав любой номер заказа.
   Физически останется 12, доступно — 9. Нажмите «Отправить», затем «Доставлено».
   Для проверки отмены создайте ещё один резерв и нажмите «Отменить резерв».
4. **FBO:** отправьте 2 единицы SKU-102 с Севера на Ozon, затем нажмите «Принять».
   На Севере останется 3, на маркетплейсе появится 2.
5. **Склады и приход:** в «Складах» добавьте и переименуйте склад, оформите на него
   приход. Архивируйте его: товар сохранится, его можно переместить на действующий склад.
6. **История:** проверьте товары, количества и маршруты. Нажмите на название операции,
   чтобы открыть подробности и её историю. Попробуйте поиск и фильтры.

Для проверки через Swagger: раскройте маршрут, нажмите **Try it out**, заполните
поля и нажмите **Execute**. Дополнительные ключи и заголовки не нужны.

## Запуск тестов вручную

Backend — интеграционные тесты с отдельной PostgreSQL и отчётом покрытия:

```sh
docker compose --profile test run --build --rm tests
```

Проверяются складские операции, нехватка, архивирование, повторные подтверждения,
конкурентные списания и откат транзакций. Основная БД не затрагивается.

Проверка стиля и остановка тестовой БД:

```sh
docker compose --profile test run --rm tests ruff check app tests migrations
docker compose --profile test run --rm tests ruff format --check app tests migrations
docker compose --profile test stop test-db
```

Frontend — нужен Node.js 22+, установка зависимостей не требуется:

```sh
npm --prefix frontend test
```

Проверяются формы, доступные действия, фильтры и обработка ошибок API.

## Основные решения и ограничения

- Backend разделён на `api/routes`, `services`, `repositories`, `models`, `schemas`,
  `core` и `db`. Frontend находится в `frontend/`, миграции и тесты — в `backend/`.
- Доступно = физический остаток − резерв. Товар в пути и на маркетплейсе учитывается отдельно.
- Остатки, статус и история меняются в одной транзакции. Блокировка строки магазина
  защищает от конкурентного списания; для прототипа записи выполняются последовательно.
- Архивирование сохраняет товар и историю. Повторное подтверждение той же операции
  не меняет остатки повторно. Повторная отправка формы создаёт **новую** операцию:
  при потере ответа сначала проверьте список операций.
- Один магазин, фиксированный каталог, целые количества и полная приёмка.
  Нет авторизации, возвратов и реальных интеграций с маркетплейсами.

## Остановка и диагностика

```sh
docker compose logs -f api web
docker compose --profile test down
```

Остановка сохраняет данные. Для полного сброса **с удалением всех данных проекта**:

```sh
docker compose --profile test down -v
docker compose up --build -d --wait
```
Видео есть в папке репозитория "видео демонстрация"
